# Local rendering protocol

This is a local single-user protocol between the original-game reader and UE. It contains observed render state, not gameplay commands. Counts, formats and identity/freshness checks are enforced in both implementations; malformed data fails closed. No network listener is used.

## Identity and world transport

Every committed world snapshot is bound to the original PID, bridge session UUID, scene-epoch UUID, monotonically increasing sequence and original capture timestamp. Catalog bindings define immutable ordered `(render id, asset)` entries, with cell generation/ownership metadata. Loading and scene changes invalidate old identities. Newly allocated native addresses do not inherit a retired object's lifetime.

Current `local/bridge/latest.json` is a `uemw.channel` **v1** locator for an inherited-owner Windows named shared-memory channel. The channel carries **`uemw.live` v5**, packed **UFB3** geometry and **UMP1 v1** render metadata. Geometry revision is **6**. The older file-backed live transports remain diagnostic compatibility paths. Only one source writer may own a checkout.

Shared memory uses a validated header and bounded latest slots with owner PID/session/nonce, commit generation, lengths and digests. A reader copies and validates an entire committed slot before adopting it; torn/in-progress/oversized copies do not become partial scene mutations. The current constants and struct layouts are in `bridge/shared_channel.py`; UE's matching reader is in `MWChannel.*`.

## Binary geometry

UFB headers are little endian `<4sHH16s16sQdIIII>`: magic, body version, reserved zero, session GUID, scene GUID, sequence, Unix nanoseconds as binary64, source PID, geometry version, binding count and reserved zero. GUIDs use four little-endian uint32 words corresponding to UE FGuid A/B/C/D. The body must match its enclosing identity and end exactly at the validated payload boundary.

There is one complete typed record per catalog binding. Hidden records carry no old pose. Rigid records carry the original thirteen float32 transform values. Native skins carry transform, original bound and palette matrices of three rows by four floats. Mutable records carry complete observed vertex/color/UV arrays as required by their asset definition. `bridge/live_binary.py` and UE `MWFrame.*` define the record discriminants and exact optional-array layout; `state_metadata.py` / `MWPacked.*` define UMP1's complete environment/material tables. Readers reject unknown kinds, trailing data, nonfinite values, invalid radii and mismatched array counts.

Current budgets include 16,384 bindings, 65,535 vertices per mutable shape, 257 palette matrices including fallback matrix zero, and a 4 MiB geometry-body budget. Native sparse weights use local `USK1` sidecars: `<4sIII>`, vertex/influence/palette counts, uint32 `(start,count)` ranges per vertex, then float32 `(palette_index,weight)` entries. Native influences are retained rather than truncated or normalized.

Local immutable triangle meshes use UEM1/2/3. UEM3 is `<4sII>` followed by XYZ float32 positions, XYZ normals, UV float32 pairs, RGBA8 colors and uint16 triangle indices. Assets/catalogs are generated solely from the user's files/live geometry and are excluded from Git.

## Binding index

`scene_bindings_version: 2` adds `scene_binding_index: {file, bytes, md5}` alongside `scene_catalog` and `scene_catalog_md5`. Its immutable `bindings-<catalog UUID>.bin` file is UBI2: little-endian `<4sHH16sII>` magic, version 2, reserved zero, raw catalog MD5, surface count and binding count. Each surface is two uint32-byte-length-prefixed UTF-8 strings: asset name and exact URD1 resource identity. Each binding is a length-prefixed render ID, uint32 surface index and length-prefixed cell key. Counts are bounded to 8,192 surfaces and 16,384 bindings; files to 16 MiB; decoded names/IDs/cell keys to 160/64/64 UTF-16 units and identities to 16,384. Invalid UTF-8, embedded NUL, duplicate names/IDs, bad indices, digests, flags, filenames, truncation or trailing bytes reject without changing the accepted table. The descriptor is part of the reader cache key. Version 1 catalog-derived binding tables remain supported.

URD1 is an exact typed canonical definition, excluding only root `shading.native_lights` and `shading.native_sun`. Sorted object keys and strings have UTF-16-unit length prefixes; arrays/objects have counts; numbers retain IEEE binary64 bits with signed zero normalized; booleans and null have separate tags. Depth/value/length budgets disable compatibility reuse for oversized definitions. Preparation computes this table off the pose owner; the full catalog worker independently derives and cross-checks every ordered binding/identity before staging resources. This removes full catalog JSON decoding from the motion reader. It does not change UFB geometry, timestamps or expiry rules.

While compatible materials stage, the renderer can apply the **current incoming** native pose to an existing surface with the same render ID, cell owner and exact URD1 identity. New materials commit after resources are ready. This exception never permits old-pose cache reuse across asset changes, and does not preserve an originally hidden, removed or replaced object.

## Native texture stages (goal 3 candidate)

An optional immutable asset `texture_stages` object, version 1, records native apply mode and sparse map rows. Slots 0..5 are base, dark, detail, gloss, glow and bump; 6..13 are decals. Rows preserve source filename, converted texture, native UV set, clamp/filter settings and optional native flip palette. Original flip indices remain in `material_frames`; no UE animation clock advances them. The current material path translates slots 0..6 and native UV sets 0..2. Additional decals/UV sets are explicitly reported as unsupported. Bump metadata retains luminance and matrix values; packed bump-format/luminance parity remains under verification.

Optional `uv_file` sidecars use UUV1: little-endian `<4sII>` magic, vertex count and set count 3, followed by per-vertex `(u0,v0,u1,v1,u2,v2)` float32 values. Original sets map to UE channels 0/2/3; channel 1 stays reserved for sparse skin ranges. Counts, file extent, finite values, path and source model/UV identity are checked. Native `NiUVController` set-zero animation uses the existing mutable UFB6 UV lane: resolved coordinates are copied, with controller type/target/selector and buffer identity fences. Other animated sets remain explicitly unsupported; their static secondary coordinates are conversion data.

An optional asset `environment_map`, version 1, binds a source effect ID to its actual converted texture palette, coordinate mode and support flag. The original global enchantment palette is read as 32 original `NiSourceTexture` pointers, with owner/palette/source identity checks. Its resolved source pointer selects `material_frames[id]`; filename patterns and reconstructed clocks do not select frames.

World snapshots add `texture_effects: {version:1, values:{id:[enabled,filter,clamp,coordinates,m00,m01,m02,m10,m11,m12,m20,m21,m22,tx,ty,tz]}}`. This bounded JSON metadata remains beside UFB3/UMP1; it shares the enclosing original capture identity/timestamp and does not renew freshness. A renderer validates the complete table before applying it, and visible effect-dependent geometry requires current values and a valid source palette index. Native sphere reflection coordinates are translated using the observed projection matrix. Other coordinate generators and water/terrain environment combinations remain explicit unsupported paths. These candidate additions do not change geometry payloads or introduce game commands.

## Camera and foreground pass

`local/bridge/camera.json` supports `uemw.camera` **v1** and **v2**, bounded to 256 KiB. V2 adds a `view` object using **`uemw.view` v1**: catalog identity, independent original timestamp, original camera basis/position/frustum, read time and up to 128 states. Visible states carry a native transform and, for skins, the exact palette/bound. Asset bone counts and all numerical bounds must match.

The reader accepts only a committed live world base with the same PID/session/scene and age under 400 ms. UE retains its full-world 500 ms watchdog. Near poses expire after 150 ms; their timestamp must be within 150 ms of the enclosing camera sample and cannot rewind a newer pose. A camera/near update does not renew the world capture timestamp.

The near reader requires two matching owned captures of the native arms camera, nodes and bones, with bounded retries. Original hide, switch, parent, model/skin, equipment and first-person/items state still apply. `view-<SHA256>.json` uses `uemw.view.layout` v1, at most 256 KiB, verified against its filename. Optional reuse signatures describe converted geometry/material and skin-weight content. Rebinding re-reads those bytes; matching old pointers alone is insufficient. UE foreground asset retention is bounded to 128 and resets with the scene.

Topology discovery uses `uemw.view.discovery` v1 in `view-refresh.json`, with PID/session/epoch, SHA256 topology signature and timestamp. Requests older than 400 ms or outside the current identity reject. They request native render discovery, never game actions. Worker-only inherited preparation pipes retain private protocol v1 and support full/layout/identity/lighting/auxiliary deltas against the exact accepted fingerprint; public files never contain pickle data.

## Native helper and controls

The x64 read helper ABI is **1**. It accepts bounded uint32 x86 address ranges and copies into owned external buffers. It has no process-write API and is not loaded into Morrowind. Read plans may be reused; sampled bytes may not be relabeled with a newer timestamp. Node ownership, model identity and exact requested-byte fallbacks remain mandatory.

Cell render roots use ownership checks against the live TES cell root slots in the same captured read. Land roots also require the cell's land pointer to match. Traversal stops at the owned root; a temporary parent above it is not an object-lifetime dependency. Root type, root-slot replacement, native hide flags, child identities, switches and actor-reference fences still apply. These are internal read-layout changes, not a wire-version change.

Presentation, witness and stop controls are local, versioned and process/scene scoped. A stop request must match its recorded run token/owner; stale PID files cannot authorize stopping another process. Normal play does not generate input or recording requests. Developer input probes require the exact private game in the foreground.

Presentation file reads/writes run in a bounded background task. Controller and renderer timestamps retain their original sample times; delayed I/O does not renew a lease. The existing 500 ms source/controller expiry rules remain in force. A disjoint side-by-side view retains its existing physical-window safety check.

With `-UEMWDiagnosticScreenshots` only, a witness request may include integer `record_seconds` from 1 through 10 to trigger the existing backbuffer recorder after startup. Its response includes `capture_folder`. Requests are not queued or extended while a capture is active. PNG capture can stall rendering and skip requests; keep it separate from timing measurements.


Dense current-transform and palette batching does not change the wire version. World transforms preserve original float32 bits rather than rounding six decimal places before packing. Nonfinite/range/identity/size validation still applies. Optional `nodes_frame_ms_end` / `nodes_spanned_frames` diagnose the actual node-copy fence; `pose_frame_ms_end` / `pose_spanned_frames` include later particle/morph reads, while `source_frame_ms_end` / `sample_spanned_frames` include metadata. Classification cannot mutate an already-owned node buffer, and its elapsed time alone does not trigger recapture. None of these fences promises atomicity across the running original engine.

Renderer performance logs now include `native_motion_frames`: distinct accepted original `frame_ms` values within each source session/scene, including partial geometry. It is a motion-application diagnostic, not a rendered or displayed FPS counter. Original sample timestamps and existing expiry/disconnect rules remain authoritative.

Native alpha comparison (rendering goal 4): an optional immutable asset `alpha_test` contains version 1, integer function 0..7 and byte reference 0..255, copied from inherited NiAlphaProperty. Functions are always, less, equal, less/equal, greater, not/equal, greater/equal and never. They remain independent of `alpha_mode` RGB blending. Shader clipping compares resolved byte alpha; native cutouts bypass the generic foliage threshold and coverage-adjusted alpha textures. No protocol motion-version change is required.

Vanilla Steam 1.6.1820 particle draw dispatch 0x6AD0A0 expands right-down/left-down/left-up/right-up corners with UV (0,0)/(1,0)/(1,1)/(0,1). It reads positions, sizes and packed colours; it does not read stored quaternions or per-particle geometry UVs. Preserve this native behavior rather than synthesize rotation/atlas animation from unused fields. Texture flip palettes remain source-selected.

Layout references for this investigation: [MWSE particle structures](https://github.com/MWSE/MWSE/blob/master/SharedSE/NIParticles.h), [MWSE alpha-property flags](https://github.com/MWSE/MWSE/blob/master/SharedSE/NIProperty.h) and [NifTools comparison enum](https://github.com/niftools/nifxml/blob/master/nif.xml). Vanilla quad/UV behavior was verified in the installed executable's render dispatch, rather than inferred from the existence of quaternion storage. Local disassembly remains ignored and is not part of the source distribution.


Water reflection witnesses report two image buffers, pending/completed/discarded counts, capture dimensions/rate, and the displayed image's source/camera sequence/timestamps and epoch. These are diagnostic additions, not a motion wire-version change. A completed image owns its matching projection and lens; pending writes never alias it. Mirrored-camera candidates carry the same captured native pose and ownership/visibility rules as other off-main-view shadow candidates. A reflection does not create a new native sample or renew an old source timestamp.


Lighting budget ranking uses nominal captured colour/attenuation independently of transient dimmer flicker. Packed and JSON environment decoders retain the same nominal selection peaks; the existing shader table still receives actual dimmer-scaled colour. This is renderer metadata derived from existing fields, with no wire-version or gameplay change. Same-epoch selection history affects only the bounded visual budget and cannot make a disabled, retired or foreign-scene light eligible.


## Native strips and lines

NiTriStripsData is expanded into the existing triangle-list mesh format with native alternating winding, resetting parity at every strip. Degenerate indices are retained. The pinned vanilla data vtable is 0x7509b0: triangle count +0x34, strip count +0x38, ushort strip lengths +0x3c and contiguous ushort points +0x40. The installed getTriangleIndices routine at 0x741e40 confirms this interpretation. Counts, data type, strip lengths and every vertex index are checked before publication.

NiLinesData (vtable 0x7501e0) has one byte flag per vertex at +0x34. Flag i joins vertex i to i+1; the final flag explicitly joins N-1 to zero. A null flag pointer draws nothing. This was verified in the installed DX8 index builder at 0x6bd190, including closure at 0x6bd2b3, rather than guessed from ambiguous serialized format notes. The original line writer at 0x6ad890 uses model positions, UVs and packed colours without normals or a skin palette; source line shading is consequently unlit and uses the current original model vertices/world transform.

UML2 is an additive local immutable mesh format: the UEM2 position/UV/RGBA8 layout and three ushort carrier indices per segment (start, end, end). Only the dedicated PT_LineList proxy interprets these carriers, using their first two indices as the actual line. They never enter triangle instancing or rasterization. The native CPU section is stored directly because UE's triangle builder intentionally discards degenerate triples. All index/array bounds are validated, collision is disabled, and native hiding/retirement/epoch rules remain unchanged. Existing readers reject this new magic safely. Mutable original vertices/UVs retain the existing UFB pose format; topology identity additionally fences the original line-flag/strip-point storage.

Primary layout references: [MWSE LinesData](https://github.com/MWSE/MWSE/blob/master/SharedSE/NILinesData.h), [MWSE GeometryData](https://github.com/MWSE/MWSE/blob/master/SharedSE/NIGeometryData.h), and [NifTools format definitions](https://github.com/niftools/nifxml/blob/master/nif.xml). Runtime strip order, line closure and omitted line normals were verified separately in the supported installed executable. Reference downloads and disassembly remain ignored local evidence.


## Installed distant scenery (uemw.distant v1)

The normal source owns a separate below-normal-priority `distant_stream.py` process. It reads the original game without injection, function calls or writes. Installed Morrowind/Tribunal/Bloodmoon CELL/STAT/LAND/LTEX/NIF records supply immutable scenery; current native persistent/modified reference lists and moved-reference lists override enable/delete/position/orientation/scale. Native all-cell discovery is invalidated at a source epoch change. Unresolved moved entries suppress their origin cell's static layer rather than resurrect an old placement. There are no distant actors, interactive-object simulations, collision, AI or independent animation clocks.

`local/bridge/distant.json` is an atomic, bounded 32 KiB `uemw.distant` version 1 lease. A live lease names source PID, source session and scene epoch, `source_sample_unix_ns`, independently observed `native_sample_unix_ns`, center grid, captured resident `excluded_grids`, content-addressed catalog/UDF names and MD5s, and binding/count/budget diagnostics. A bake is checked against newly sampled original reference state and the same source epoch before publication. A heartbeat only renews genuinely resampled static state, never a cached native timestamp. Shared-channel contention drops an attempt; file sharing conflicts drop publication after bounded retries. Both timestamps expire after 500 ms. Non-live, foreign-source/epoch, malformed or expired data hides this layer. The parent also gates it on current original scene visibility.

UDF1 is little endian `<4sI>` (`UDF1`, count), followed by exactly count `<I13f>` records: visible 0/1 and the original-space rotation9, position3 and scale. Exact length/digest/count/finite values and canonical filenames are validated before adoption. These are installed static derivatives plus separately read native overrides, **not** original 50/60 Hz motion captures. Distant witnesses explicitly identify that scope. The live pose protocol is unchanged.

The prepared halo is at most 7x7 cells, 4,096 bindings, 1,024 mesh definitions and one million distinct vertices. LAND uses every fourth interior sample, retaining all 65 real samples on every border; no invented skirt geometry is used. A separate explicit `terrain_tiles` catalog array retains original swizzled VTEX/LTEX assignments. It permits at most 16,384 paint tiles in a 128x128 assignment grid, 64 layers, 256-pixel distant color/detail arrays and the existing 192 MiB pool cap. Native terrain continues using its 512-pixel pool. Full catalogs remain at most 8 MiB.

The auxiliary UE geometry owner shares the current native environment texture and original fog. It has no frame/camera reader, own lighting, tick, input or collision; distant shadows/reflections are omitted. It reuses the existing bounded resource preparation and rigid buffers. Original resident cells always win: union the worker's captured resident set, the current native center's 3x3 neighborhood and **all cells bound by the active native catalog**. This conservative rule can defer newly released distant coverage while preventing asynchronous double rendering. Unchanged static submissions are reused until pose/catalog or residency gates change.

Generated licensed derivatives stay under ignored `local/distant-assets`; source archives contain none. Sixteen completed generations protect decoder readers, under a 512 MiB cache budget. Models with unsupported classes/controllers, small objects below radius 64 and objects beyond instance/mesh/vertex budgets are explicitly omitted. Original live rendering resumes when their cells become resident. Native fog can obscure most of the distant layer at vanilla view distance; it is not extended silently. World completeness, arbitrary plugin compatibility and pixel parity are not claimed.

Layout references: [MWSE Cell](https://github.com/MWSE/MWSE/blob/86c2901930feb61b963734dadb9c648d0277817f/MWSE/TES3Cell.h), [Reference](https://github.com/MWSE/MWSE/blob/86c2901930feb61b963734dadb9c648d0277817f/MWSE/TES3Reference.h), [DataHandler](https://github.com/MWSE/MWSE/blob/86c2901930feb61b963734dadb9c648d0277817f/MWSE/TES3DataHandler.h), and [NifTools format definitions](https://github.com/niftools/nifxml/blob/master/nif.xml). Native saved/static state, scale encoding and materialized reference behavior were separately checked in the supported executable and private checkpoint. Reference downloads remain ignored; no third-party source is incorporated.

The opt-in diagnostic witness accepts `distant_scenery` to hide/show this owner and `distant_surface_fog` to bypass/restore its existing material fog. These require `-UEMWDiagnosticScreenshots`; they are not normal launch settings. Inspecting un-fogged far geometry also requires bypassing the completed-scene fog pass (`water_fog_mode=0`). Restoring material fog and mode 1 returns the captured native atmosphere.

## Native original UI (uemw.ui v1)

The normal source owns a separate below-normal-priority `ui_stream.py` worker, capped at 20 captures/sec. It reads the original menu camera/scene, resolved NiTriShape glyphs/images, colours, transforms, visibility and UI ownership. Layout, strings, wrapping, font selection, cursor position, menus and actions remain native. It reads CPU NiPixelData for generated fonts/maps and locally converts installed UI images, including Icons/Fonts/BookArt. RGBA/RGB24 and the observed XRGB32 save thumbnails are supported. It never captures a game window, calls the game or writes its memory.

Each attempt recopies a bounded previous-address page plan into owned memory (at most 16 MiB); new allocations enter that plan through exact reads. Actual end fences check source/camera/menu identity, node visibility/hierarchy, geometry counts/storage and UI layout. Ordinary movement/refcounts are not destruction. Projected geometry can be reused only when its complete current native buffers, transform, material/colour, camera and layout key match. UI meshes already contain the original's resolved clipping; applying cached Element clip boxes again cropped journal text and post-layout page-number anchors. Only final viewport clipping is added, with original UV/RGBA interpolation. No font or layout rules are rebuilt.

`local/bridge/ui.json` is an atomic, bounded 32 KiB `uemw.ui` version 1 lease: source PID/session, sequence, unchanged capture-start `sample_unix_ns`, viewport, exact active menus, content/digest references and diagnostics. `UUI1` is little endian `<4sHH16sQdIIII>` (56 bytes: magic, version 1, reserved zero, source GUID, sequence, original timestamp as binary64 nanoseconds, PID, width, height, draw count). Each draw has `<4I>` (native shape pointer, texture index or 0xffffffff, vertex/index counts), then vertices `<4f4B>` (projected XY, UV, RGBA8) and triangle ushort indices. Limits: 2 MiB body, 2,048 draws, 65,536 vertices and 196,608 indices. Canonical session/sequence filenames, MD5, exact lengths, identity, finite values, indices and budgets are verified before adoption.

`UTX1` images contain `<4sII>` magic/width/height then original RGBA8 pixels, at most 1024x1024. Canonical filenames are SHA256 digests; manifest MD5 and exact dimensions/byte counts are independently checked. Each frame uses at most 128 images/64 MiB. UE uploads at most eight new images or 2 ms of uploads per tick, preserving the prior leased frame until resources are ready. Disk history retains sixteen frames under a 256 MiB image budget; the GPU cache is bounded at 128 MiB. All licensed derivatives stay in ignored `local/ui-assets`/`local/bridge/ui-frames`.

UE's Canvas uses explicit translucent blending, original vertex colours/UVs, and aspect-preserving viewport placement. Alpha-zero fader/pick planes cannot blacken the scene. This is approximate depth/painter compositing, not arbitrary animated 3D UI or pixel parity. Frame timestamps expire after 500 ms; original PID/session and active menus must match before unified presentation. UI rates/ages are separate from world/weapon motion rates.

The supported inventory portrait is a native GPU-only NiRenderedTexture with no readback buffer. A `native_regions` entry must match the exact original character/map render-target pointer, its owning active MenuInventory/MenuMap, finite viewport-bounded projected rectangle, and the same source lease. UE records the validated rectangles in its heartbeat. The passive controller subtracts only these regions from its own UE HWND using SetWindowRgn, exposing the existing original UI beneath. No original-window styles/input change, video capture, invented portrait or injected readback is used. Separate-window mode shows that region in the original window instead. Unknown rendered targets fail closed.

The controller binds the exact private original and project renderer HWND/PIDs. OS input goes directly to the original once; runtime UI and presentation send zero input events. Busy shared-memory copies retain the exact prior snapshot until ordinary expiry. New menu resources have a bounded 750 ms transition allowance (150 ms for same-menu UI interruption). Native loading exposes the original; after loading ends, at most twenty seconds are allowed for fresh source/new UE resources to become ready. Normal menus recover without changing scene renderers. True source/render/UI freshness faults latch the original fallback until explicit launch/rearm, preventing oscillation. Other apps, unknown UI and process disconnects uncover the original. The independent watchdog remains active.
