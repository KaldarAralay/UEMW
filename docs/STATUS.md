# Status and supported scope

UEMW is an experimental Windows source alpha. It renders actual original-game geometry in a packaged UE 5.2.1 client while unmodified Steam Morrowind remains authoritative. It is not a completed full-game port or a compatibility promise for arbitrary mods/versions.

Implemented paths include original interiors and bounded loaded exterior cells, native terrain textures/blending, sparse bone palettes, player/NPC poses, first-person camera correction, native material/texture state, sampled lighting/fog/weather, shadows, water/underwater appearance, sky/celestial objects, rain and foliage presentation. Rendering parity is incomplete. The original UI remains a separate original-game window by default.

The latest weapon regression repair was tested in live Seyda Neen with an equipped iron longsword, walking, repeated draws, original reloads and view-mode switching. Exterior/reload checks matched 213 exact pose/placement witnesses with all eighteen foreground sections present; eight draws took roughly 0.36–0.51 seconds including native animation and observer polling. These are bounded local tests, not a guarantee for every item or long session. Immutable opaque foreground assets have the independent fast path; other effect/material cases retain older paths.

**Earlier rendering-hitch and transient-visibility repairs:** Cell-root ownership now follows live TES cell slots, avoiding false cell/NPC removal during temporary reparenting. Binding indices, cache rebasing and presentation I/O move work off the game thread; material selection and invalidation remain incremental. The final short walk measured 16.67 ms median, 16.69 ms p95 and 31.67 ms worst game-thread intervals, with no samples over 33.33 ms. This is not a locked-60 or every-frame visibility guarantee; the paired preserved-client run had a lower maximum under less streaming work. See [performance evidence and limits](PERFORMANCE.md).

Those are not display/scanout FPS measurements, and a locked 60 FPS target is unproven. Whole-world state rate can be lower than camera/foreground rate. Mod compatibility, full-world coverage, all effects/body-part combinations, exact shadows/material parity and sustained stability remain open.

Source tests use owned synthetic data and Windows allocations, without game/engine files. Packaged UE tests use generated owned fixtures. CI runs the former without licensed dependencies; full packaging and live play remain local checks. Setup verifies the documented toolchain and refuses unsupported executable hashes instead of guessing offsets.

**Cadence and compatible resource handoff now meet the first two rendering-roadmap targets in the bounded fixture:** latest walk 56.30 distinct original captures/sec and 54.66 distinct original frames applied/sec, including 7.52 partial applications/sec. Complete/partial pose age p95 was 38.08/43.67 ms; 60 compatible resource retargets caused zero rebind hides. UBI2 removes full catalog decoding from the motion reader. New/incompatible resources still prepare asynchronously; full-world completeness and locked 60 displayed FPS remain unproven. Verification includes 315 Python tests, 27 packaged UE tests, exact NPC/weapon witnesses, native boundary/interior/door transitions and fresh-session disconnect recovery; 32 protected saves were unchanged. GPU/scanout limits and failed-candidate findings are explicit in [performance evidence](PERFORMANCE.md). See the [ordered rendering goals](RENDERING-ROADMAP.md).

The GitHub preparation work covers layout, build/setup discovery, dependency isolation and launch supervision. The subsequent hitch work changes renderer execution/caching; it keeps the same visual settings and original gameplay authority.

Native secondary stages now preserve original detail/glow/decal maps, secondary UVs, independent flip palettes and sphere environment effects, including original enchantment frames and resolved set-zero UV animation. 325 Python / 28 packaged UE checks and exact live effect/UV/weapon/NPC regressions pass. Material combinations and remaining performance limits are explicit in the [rendering roadmap](RENDERING-ROADMAP.md); the next implementation is particles/transparency.

Particles now follow the verified vanilla corner/UV orientation, with source alpha comparison independent of blending. 329 Python / 29 UE tests and 48 real GPU byte-boundary comparisons pass, plus sampled original fire/smoke, spell, rain, weapon and NPC checks. Whole-game sorting/pixel parity and isolated stalls remain explicit limits.

Water reflections now use two owned HDR targets at 640 pixels and a phase-preserving 30 Hz schedule. Completed images retain their matching camera/lens/epoch and never alias the target being written. Original world transparency and bounded shadow maps are included; mirrored-camera source culling supplies current native poses. 330 Python / 30 UE tests, an actual GPU transparency comparison, shoreline/swim/resurface, reflected native effects, moving NPC, weapon, reload and disconnect/recovery checks pass; 32 protected saves remain unchanged. The matched daylight pair measured about 0.57 ms extra median GPU time with reflections enabled; a 52 ms GPU outlier remains. Main-camera particle orientation, a bounded reflection distance, excluded foreground/rain and lack of capture temporal antialiasing remain limitations. Lighting/shadow coverage completed its bounded milestone below.


Light-budget selection now ignores native object-selection radii and transient dimmer flicker when ranking nominal contribution. Original flicker, colour, attenuation and per-object membership are preserved in shading. Shadow selection uses nominal irradiance and hysteresis; sun cascades follow the captured native horizon within a bounded range. 334 Python / 30 UE tests, actual interior shadow darkening, stable interior/day/night camera turns, weapon/NPC/reload/disconnect and protected-save checks pass. Crowded-shore performance remains below 60 FPS capacity; checkpoint median GPU time was 16.29 ms with a 44.43 ms maximum. The limits and measurements are in PERFORMANCE.md. Geometry coverage completed its bounded milestone below.


NiTriStrips and NiLines now have validated original-buffer translation; lines use actual GPU line primitives with no UE collision. 340 Python / 31 packaged UE tests and a separate GPU pixel test pass, along with normal live scene/weapon/NPC/reload/disconnect/save checks. No examples of these two serialized data types were found in the 7,320 installed base-game/expansion NIF entries; this closes assumed format gaps using owned fixtures, without claiming a visible vanilla omission was repaired. Distant scenery is implemented below; unified native UI is next.


The renderer now prepares a bounded installed-data distant terrain/static halo beyond the native resident cells. A separate read-only worker merges original enable/delete/move/scale overrides; UE excludes both readers' resident envelopes and active native catalog cells. Unchanged static submissions are reused. Geometry, textures and terrain paints come from the user's installed game; no distant actors, collision, AI or independent animation are added. Original fog is retained and can obscure most far scenery at vanilla view distance. Controller-driven/unsupported NIFs, small props, budget overflow, distant shadows and far reflections remain omissions.

350 source tests, 32 packaged UE tests and an actual GPU fixture (54 geometry pixels) pass. The GPU-only inventory portrait uses a bounded original UI region beneath the passive overlay. Native loading/failure fallback remains available; the default separate-window launcher is retained. No gameplay/UI rules or portrait are rebuilt.

363 source tests, 33 UE tests and a real GPU transparency comparison pass. Exact weapon/NPC checks passed. Short walking measured 19.68 ms median GPU time, with a 39.84 ms maximum; UI observation ages were about 173–272 ms median by phase, up to 359 ms. All nine ordered milestones have bounded implementation/verification evidence; this is still an experimental renderer, not complete visual parity or a finished full-game port.
