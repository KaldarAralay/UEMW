# Development

Run the [setup procedure](SETUP.md) before a full build. Normal source changes live in `bridge/`, `native/`, `shaders/` and `ue/UEMorrowind/Source`. Project materials are generated from source; do not check in `Content`, `Binaries`, `Intermediate`, `Saved` or DDC outputs.

## Tests

```bat
Test-UEMW.cmd -Repository
Test-UEMW.cmd -Renderer
```

The first runs the Python suite and public-file audit. The second also runs all 33 owned-data checks in the packaged UE executable. `python tools/run_tests.py` is the direct unit-test entry point; it sets the runtime/developer/test import paths. Tests need Windows/Python/NumPy/Pillow, not game data or UE. Build `tools/build-read-batch.ps1` to include the real owned-allocation native ABI tests. Four optional crash-watchdog tests skip unless the separate diagnostic helpers were built with `tools/build-diagnostics.ps1 -IncludeTests`. CI uses `-AllowNewerCompiler` only for the small read helper; it does not relax the full UE build's 14.34 pin.

The optional `tools/test-client-alpha-gpu.ps1` uses the packaged client and owned textures to check all eight native alpha comparisons immediately below, at and above a byte threshold, for masked and translucent policies. It runs hidden in an isolated source root, writes a fresh diagnostic log, records no video and is separate from the NullRHI tests. Its default is D3D11; add `-RHI d3d12 -EnableRHIThread` to verify the normal submission backend. The script checks the actual backend and thread state. Other `-Test` choices cover native UI, mutable attributes, rigid surface/shadows, reflection membership, water ownership and skin poses. `NativeSkinPoses` compares real GPU skin pixels with independently CPU-deformed static geometry through translation, rotation, nonuniform/mirrored scale and hide/restoration, without borrowing a running game's geometry or lights.

`tools/test-client-alpha-gpu.ps1 -Test NativeVertexAttributes` checks the selective mutable-mesh upload path against UE's general procedural path in actual GPU pixels. Position/normal, UV and colour changes must preserve the proxy, update the expected channels and match the reference; identical data must enqueue no upload. This uses owned synthetic geometry/textures, independent of the game installation.

`tools/test-portability.ps1` checks PowerShell syntax, nondefault Steam-library discovery, path spacing and actual venv worker PID identification using owned fixtures. Full setup was designed to be repeatable and to report all missing build prerequisites before installing packages or changing private files.

After stopping this project's UE view/bridge:

```bat
tools\run-powershell.cmd -NoProfile -ExecutionPolicy Bypass -File tools\package-client.ps1
```

The build discovers the configured compiler/SDK, compiles the editor module and small native helpers, generates project-owned materials/probes if needed, then cooks/stages the runtime under `local/client`. `local/client/build-info.json` records source/binary hashes. Shader changes belong in `shaders/`; `tools/build_materials.py` constructs the UE material graph and embeds that source. Use `Setup-UEMW.cmd` to repeat the complete dependency/preparation/build/test flow.

## Live diagnostics

Developer probes live in `dev/diagnostics`; invoke them through `python dev/run.py <name> [arguments]` so child processes inherit the correct import paths. Some probes generate ordinary original-game input or need a disposable fixture/save. They are opt-in and never run at normal startup. Read their module docstrings before using them. Do not run a survey as proof that the game is broadly playable.

Useful starting points include `benchmark`, `profile_bridge`, `check_first_person_motion`, `check_native_motion`, `check_render_stability` and `check_focus_stages`. A current first-person probe is `python dev/run.py check_first_person_motion --pid <private-PID> --seconds 12 --draw-cycles 2`; it expects the equipped eighteen-section iron sword/hands fixture and the original focused. Reload a disposable checkpoint afterwards.

For UI response, use `python dev/run.py check_ui_latency --pid <private-PID> --label repeat --events 24 --transitions 12` after loading a safe disposable checkpoint in unified mode with `-PresentationStats -DiagnosticScreenshots`. This verifies compiled source/package hashes before input, waits for both resource owners, matches native cursor geometry and menu transitions to the immutable bodies actually drawn, then runs a short walking check and leaves the game paused. Read the resulting latency and frame-interval percentiles separately: its `passed` flag establishes complete identity/observation coverage, not achievement of a performance threshold. `check_ui_hover --pid <private-PID> --topic Background --label repeat --events 16` requires an existing genuine NPC dialogue and matches original topic glyph colours independently of the cursor. Neither tool saves, records video or measures scanout/input-to-photon latency.

`tools/analyze-render-trace.ps1 -Events -StartSeconds 10 -EndSeconds 15 -Threads GameThread -Timers 'UEMW_*'` exports a bounded subset of an existing diagnostic trace. Render-thread names may have a suffix (use `'Render*'`). Restrict timer names as well as time/thread filters; a full renderer event export can exceed a gigabyte even for a short run. Stream large CSVs instead of loading all rows into memory. Detailed tracing adds overhead and its frame timings must not be presented as ordinary-play acceptance results.

`python dev/run.py check_present_queue --pid <private-PID> --label queue --seconds 7` runs a bounded 3/1/1/3 queue-depth comparison with VSync held off. It requires the focused private game, a safe exterior checkpoint, the normal 1024x768 native viewport and unified PresentationStats/DiagnosticScreenshots. Each case validates the actual device depth, waits for both resource owners and measures original walking. It restores the preceding controls and pauses on exit; it writes no saves. The older `presentation_sync` diagnostic changes queue depth as well as VSync and cannot isolate those effects by itself. The initial independent comparison did not improve display pacing; defaults were preserved.

On the explicit D3D11 fallback, add `--sync-paced` to compare the 60 FPS CPU cap with VSync pacing at fixed queue depth 3, using a measured 60 Hz output. The first capped case must confirm that refresh before further cases. Read actual DXGI observations separately from CPU intervals; neither is photon timing. Normal unified D3D11 fallback chooses output-only pacing automatically on 59/60 Hz outputs; the D3D12 default retains the CPU cap alongside VSync. Hidden/unfocused/stale-owner states use VSync-off CPU pacing. Lower explicit FPS caps and other output rates retain the CPU cap. Set `UEMW_DISPLAY_PACING=0` before a new renderer for the old comparison path. Explicit pacing witness controls suspend automatic selection until renderer restart. The D3D11 queue diagnostic does not configure D3D12 queue depth. Both rejected mutable-buffer and cached-draw candidates were removed; the production proxy keeps selective uploads through its validated dynamic draw path. The GPU fixture separately checks real normal-only illumination using both owned native-light-table and owned UE-directional-light references.

UI source changes require restarting the source process: normal launch deliberately reuses a healthy source, whose Python modules are already loaded. C++/shader changes additionally require repackaging. The live timing tool checks compiled/package hashes; record the new source session and runtime source hashes separately when changing only Python. Current source snapshot slabs contain owned immutable bytes, never views into the native helper's reusable scratch. A geometry cache hit can skip transform decoding only when all freshly copied key bytes exactly match the previously validated result.

Catalog workers retain their own decoder-validated immutable binding table through GPU staging, even when newer source work overtakes them. Only IDs/assets/cell ownership are shared; transforms, visibility and palettes still come from each fresh native frame. Completed `TFuture` results are reset after adoption: UE 5.2 `Get()` copies the shared result pointer, retaining the DTO until the future is reset or replaced. Superseded staged data and completed futures are retired off-thread as plain arrays/strings, with no UObjects or reusable poses in cleanup tasks. Slow catalog phases above 8 ms are logged, with snapshot subphase timings for diagnosis. Cold geometry/terrain uploads can still exceed a frame budget.

Catalog job keys and first-person priority order are prepared on that worker. CPU definition adoption yields after 2 ms or 128 entries per call; this is a scheduling budget, not a hard upper bound on an individual allocation or an entire UE frame. Incremental selection indices stay valid between batches, and incomplete definitions remain ineligible for ready-cache hits after supersession. `UEMW_CATALOG_DEFINITION_BATCHES=0` before a fresh renderer launch retains the original game-thread ordering/unbatched adoption for matched comparisons. An existing renderer keeps its launch setting. Completion logs report owner, catalog, entry/batch counts and total/maximum adoption CPU scopes; general catalog-stage timings also include snapshot, terrain, textures, materials and binding work. Owned tests force one-entry batches, verify old bindings/materials survive, supersede a partial load and check exact final classifications against the retained reference.

Terrain array bulk allocations and mip copies are prepared on that worker. The game thread adopts single-use platform data into ordinary `NeverStream` transient arrays, preserving the existing UE sampler, colour space and all mips. These payloads initialize once; a new renderer recreates them from installed data. `UEMW_TERRAIN_PREPARED_DATA=0` before renderer launch retains the earlier copying path for comparison. This changes CPU preparation, not the GPU upload API. A polled render-command fence gates promotion; no CPU wait is introduced. Existing terrain materials rebind at most 128 entries or 2 ms per call, with matching texture/layout parameters per material. The completed signature is invalidated during rebinding so even a rapid return to the preceding grid cannot skip unfinished work. Temporary older valid neighbour blending can remain until those material jobs finish.

Animated native rigid parts that acquire shear keep their exact CPU affine representation once ready. An already displayed rigid part receiving its first sheared frame allocates CPU capacity before the old representation is hidden, then fills it from that current native pose. This one-time allocation can still cost CPU time; no previous pose is replayed and the matrix tolerance is unchanged. Lighting-only skin handoff can also recover its shared mesh directly from the validated existing component if an earlier alias pass ran before that component became ready. Real asset/cell changes, native hides/removals and source expiry retain their existing checks.

`tools/test-client-alpha-gpu.ps1 -Test NativeTerrainBlend -RHI d3d12 -EnableRHIThread` compares the prepared and original arrays through the actual terrain shader at three viewing scales. The D3D11 fallback is checked by omitting the thread switch and selecting `-RHI d3d11`. The owned terrain test also checks every mip/layer byte, cancellation, one-time ownership transfer and a forced one-material-per-call handoff. Geometry tests check changing native shear, stable component identity, current vertex coordinates and visibility, plus the late-ready skin alias and native hiding.

The packaged Development launcher and headless/GPU checks select UE's built-in Binned3 allocator. Set `UEMW_ALLOCATOR=binned2` for the retained comparison path; invalid values fail before launch. `start-session.ps1` restarts a managed renderer with a different allocator argument while preserving its healthy native source. Check the actual `allocator` witness field / `LogInit: Allocator` line. The engine and garbage collector are unmodified. This command-line selection is validated on the installed Win64 UE 5.2.1 Development client, not Shipping or other toolchains. Direct executable launches bypass the launcher selection.

Unified presentation fits the original game's client rectangle. The renderer's startup width/height arguments can therefore differ from its eventual viewport. Pass the actual dimensions reported by runtime performance windows to `benchmark`; do not label a fitted 1024x768 collection as 1920x1080 merely because of launcher defaults.

`witness([], memory_trim=True)` in a `-DiagnosticScreenshots` session explicitly runs a memory trim and reports `memory_trim_cpu_ms`; never include those deliberate stalls in ordinary-play benchmarks. The allocator's work depends on allocation history. First-person resource regressions now cover an older world binding with the same native id and obsolete queued allocations, in addition to exact poses, native hiding/removal and expiry. A failed post-draw probe retains the full UE witness and current camera packet, including expected resource/near assets. Missing independently retained source samples are failed observation coverage, not proof of a displayed disappearance.

UI now publishes UI/v2 metadata and unchanged UUI1 bytes over `uemw.channel/v1`. `UEMW_UI_SHARED_CHANNEL=0` before starting a new source retains file UI/v1 for comparison; restarting only UE does not reload the Python producer. Diagnostic body files remain available for independent exact-frame verification. Source sequences reserve an identity before every capture attempt, including a busy/failed publication. `ui_pipeline.read_parts_ms` separates header parse, texture validation, body IO/hash, geometry decode, manifest/channel fetch and known-texture copy; times are CPU phases, not GPU completion. The owned shared fixture can accept an explicit generated fixture directory; the GPU UI script starts/stops that isolated helper and tests actual Canvas pixels from UI/v2 on either backend.

Default launch is passive two-window D3D12/SM5 with a separate RHI submission thread and original rendering enabled. `Start-UEMW-Unified.cmd` (or `tools/start-session.ps1 -Overlay`) translates native UI over the UE scene. Unified presentation uses capped VSync on a measured 59/60 Hz output while its owner lease is fresh and the original is focused. `tools/start-session.ps1 -Overlay -RHI d3d11` selects the retained D3D11/no-RHI-thread fallback; both formats are cooked locally. `-Editor`, `-DiagnosticScreenshots`, `-DiagnosticTrace`, `-PresentationStats` and crash capture are explicit development options. Alternate launchers are under `dev/launchers`. Normal launch records nothing. Measurements must distinguish actor ticks, applied state rate, GPU timestamps and actual displayed frames. D3D11/D3D12 GPU timestamp scopes differ in UE 5.2; do not treat them as a matched GPU speedup or assume the D3D11 latency cvar controls D3D12's queue.

Full-world and per-cell membership hashes are expensive and disabled during normal play. For a focused diagnostic run, set `UEMW_MEMBERSHIP_DIAGNOSTICS=1` before starting a new renderer (or pass the renderer argument `-UEMWDiagnosticMembership`). The small health/performance reports and independent fail-safe heartbeat remain enabled.

For transient visibility diagnosis, `UEMW_VISIBILITY_DIAGNOSTICS=1` logs renderer scene/skin visibility transitions. `UEMW_VISIBILITY_TRACE=hitch` on a newly started bridge records source skin visibility/parent changes under ignored `logs/`. These are expensive opt-in diagnostics; disable them for performance comparisons. Scene-hide transitions remain logged normally. A diagnostic renderer also accepts `check_native_motion.witness(ids, record_seconds=4)` for a bounded image check; this is not a performance benchmark or an every-frame visibility guarantee.

## Native lighting comparisons

Use `tools/start-session.ps1 -TwoWindows -DiagnosticScreenshots` for an original/UE image comparison. A capture of the original window beneath the unified overlay can include UE pixels; it is not an independent original reference. Match the actual client viewport, camera and paused native light state, and exclude original console/HUD/tooltip regions from image metrics. Keep captures under ignored `logs/`.

In the existing diagnostic Python environment, `check_native_motion.witness([], native_light_reference='vertex')` selects an unshadowed, original-vertex-colour lighting reference on solid materials; `'pixel'` evaluates the same captured light inputs per pixel. Both preserve native per-object light membership and display-RGB conversion and disable UE direct lights without changing the tone curve. The older `visual_profile='reference'` also changes tone mapping and light selection, so it cannot isolate those lighting differences. These diagnostics do not claim full fixed-function or whole-game pixel parity.

For colour comparisons, set `UEMW_TEXTURE_UPGRADES=0` before starting a fresh renderer and verify `upgraded_textures == 0` in its witness. An already-running renderer is not reconfigured by changing its parent's environment. Restore normal optional enhancement by removing that environment variable and restarting the renderer. These comparisons are separate from default enhanced PBR/shadow presentation.

`witness([], native_colour_ramp=True)` adds an owned eight-colour strip through the actual scene/post-process/backbuffer path. It expires after five seconds; `native_colour_ramp=False` removes it immediately. Sample swatch centres across the real viewport, compare their RGB bytes, and exclude this diagnostic from performance measurements. The neutral SDR camera disables UE vignette; post-process output must be checked separately from an HDR render-target shader test.

Restore normal rendering with `witness([], native_light_reference='off', native_irradiance='pixel', shadow_maps=True)`. `native_irradiance='vertex'` compares combined Gouraud primary colour against the default pixel path. Lighting comparison requests are accepted only by an explicitly diagnostic client; restarting normally restores defaults. No game memory, gameplay light flags or save files are modified by these renderer requests.

`tools/test-client-alpha-gpu.ps1 -Test NativeLighting -RHI d3d12 -EnableRHIThread` checks the cooked lighting shader against owned CPU-prelit mesh colours. Repeat with `-RHI d3d11` for the fallback backend. This is a shader calculation regression, separate from actual original-game comparisons and performance measurements.

The same GPU test also compares a dark base-only texture times a constant vertex colour against an independently CPU-multiplied display-RGB reference. Secondary-stage presence must not change that operation's colour space. Saturation and static-upload tests alone do not catch this error.

An optional read-only original draw-state probe is supplied in `native/d3d8_light_probe.hpp`; it is not a normal dependency or launcher component. It can be compiled into a separately obtained [d3d8to9](https://github.com/crosire/d3d8to9) source tree under `third_party/d3d8to9`: include `../../../native/d3d8_light_probe.hpp` in `source/d3d8to9_device.cpp`, call `UEMWLightProbe::Present()` in its `Present`, and call `UEMWLightProbe::Draw(ProxyInterface,unsigned(PrimitiveType),CurrentBaseVertexIndex,MinIndex,NumVertices,StartIndex,PrimitiveCount)` before `DrawIndexedPrimitive`. Use a Win32 **Release** build with the existing C++ toolchain; the upstream RelWithDebInfo configuration mixes debug defines with a release CRT on the locally tested source. No automatic download, installation or private-DLL replacement is provided by this diagnostic.

For an explicit private-game diagnostic, preserve the existing private `d3d8.dll`, close that private game before temporary replacement, and keep all Steam files untouched. A one-frame `uemw-light-probe.request` file beside the private executable produces bounded `uemw-light-probe.jsonl` draw-state/available read-only vertex samples. Match source vertex positions/counts/transforms before accepting colours/light indices; cached UI layout/unused fields are not world evidence. Earlier raw probe output contained nonfinite unused UI attributes; the current header writes them as null. Restore the exact preserved graphics DLL before normal launch or performance measurements: the temporary standalone d3d8to9 probe does not reproduce the pinned DXWrapper presentation/pacing configuration. Keep all draw dumps and game-derived data under ignored `local/` or `logs/`.

## Optional local texture enhancement

The normal build uses your original textures plus UEMW materials. It does not need PyTorch or downloaded model weights. The optional `tools/texture_upscale.py` can bake local enhanced textures from your own game; it requires a separately installed CUDA-capable PyTorch environment plus psutil. Use `--help` for modes and `--download-model` only when you want its hash-pinned Real-ESRGAN model. Close the project game/view before an offline GPU bake. Output, model weights and the enhancement index stay under ignored `local/`. The original-texture path remains available by setting `UEMW_TEXTURE_UPGRADES=0` before launch. See [third-party notices](../THIRD_PARTY_NOTICES.md).

## Publication boundary

`python tools/audit_repository.py` examines exactly what Git would publish, including accidentally staged ignored files. It rejects game/converted/binary artifacts, private/generated directories, personal absolute paths, obvious credential patterns and broken public Markdown links. Source exports without `.git` use the same public/private directory boundary.

```bat
tools\run-powershell.cmd -NoProfile -ExecutionPolicy Bypass -File tools\package-source.ps1
tools\run-powershell.cmd -NoProfile -ExecutionPolicy Bypass -File tools\audit-source-package.ps1
```

The source ZIP is generated in ignored `local/distribution`, with a content-hash manifest and no game/assets/binaries. Do not upload the entire working folder or generated client as a source archive. Existing milestone notes, experiments and local evidence are archived under ignored `local/archive` and `logs`; they are not dependencies of a fresh build.

The public GitHub workflow runs owned-data tests and the repository audit on Windows, without Steam or UE. Full build/live checks require the separately installed licensed dependencies. Rendering changes should include their actual local verification and limitations in the PR description.


## Reflection membership diagnostics

Water captures retain their component membership and patch native visibility, creation/removal and asset replacement. Camera, transforms, skin palettes, material state, capture cadence, resolution and image-ownership fences still update through the existing paths. Definition retirement, inclusion/blend classification changes and scene reset reconcile the complete membership.

`tools/test-client-alpha-gpu.ps1 -Test ReflectionMembership` compares actual HDR pixels against a freshly scanned component list after movement, hiding/restoration, removal and recreation. It also checks same-count replacement and reset cleanup. The test uses only owned geometry/material data. Run `tools/test-client-headless.ps1` for the complete 34-test packaged suite.

For a performance comparison, set `UEMW_REFLECTION_MEMBERSHIP_CACHE=0` before starting a new renderer. It uses the original full-scan path without rebuilding the new reverse maps in the baseline. Restart with the variable unset to restore the default incremental path. Restore the same private checkpoint and camera, warm both resource owners, and require visible unified presentation with identical pacing/quality settings before measuring. A launch that reuses an existing renderer cannot change its environment setting.


## Native rigid component placement

Ordinary world batches containing one nonzero-scale rigid object can keep an identity instance and carry the exact native world transform on the component. This avoids UE 5.2 instance-buffer recreation for subsequent native movement. Stable instance IDs remain intact. Shared batches, zero-scale states and camera-relative/foreground/water/rain geometry use the original instance-matrix representation; transitions update the buffer before rendering. Collision and simulation remain disabled in UE.

`tools/test-client-alpha-gpu.ps1 -Test RigidComponentTransforms` compares actual native-lit pixels with the original representation through movement, nonuniform/mirrored scale, membership changes, hiding and recreation. The packaged headless suite now contains 37 tests; GPU-only assertions require the separate GPU runs described above. `UEMW_RIGID_COMPONENT_TRANSFORMS=0` before a new renderer launch selects the original representation for comparisons. An existing renderer retains its launch setting.


Performance and UI observers select the `renderer_log_file` published by the matching fresh renderer heartbeat. Rebuild the client after updating these observers; old clients without that field are rejected. Do not rename active logs or substitute the newest file. The benchmark output records the selected renderer PID/path and `ue_native_geometry_cpu_ms` summaries for total, catalog/material, compare/resources, changed submissions, reconciliation and rigid flush. They are main-owner CPU apply phases, nested within total and sampled in ordinary performance windows; they are not individual display-frame timelines. No command-bypass candidate is enabled by ordinary launch.


Catalog handoff classification is prepared off-thread and independently checked by the optional `catalog_classification_matches` witness. `UEMW_CATALOG_HANDOFF_PLANS=0` before a new renderer selects the reference commit/scan path; ordinary launch enables preparation. An existing renderer retains its launch setting. Both comparison paths preserve the same source identity, pose, visibility and resource safety checks. Benchmark output includes `ue_catalog_bind_ms` and `ue_rigid_membership_scan_ms`; no events in a timed interval are reported as unknown, not zero. The 36-test packaged suite includes cached metadata, identity mutation, exact reference parity and populated reconstruction coverage. See PERFORMANCE.md for timing limits and retained rejected evidence.
